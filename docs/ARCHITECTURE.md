# 데이터·권한·상태 설계

## 책임 경계

- Next.js 정적 프런트엔드: UI, PDF.js canvas, Fullscreen API, 키보드 입력, 업로드 진행률, 서버 시계 보정 표시.
- Supabase Auth: 검증된 사용자 ID와 이메일. 행사 역할은 JWT의 임의 메타데이터가 아닌 `members` 테이블로 결정.
- PostgreSQL: 행사·팀·배정, 불변 PDF 버전, 발표 상태, 평가 기준 버전, 심사 CAS, 요청 중복 처리. 변경 권한은 테이블 직접 쓰기가 아닌 명시적인 RPC에 집중.
- Supabase Edge Function: 인증→행사·팀 소속 확인→크기 제한→PDF 구조 검사→비공개 저장→원자적인 제출본 교체.
- Realtime: `event_updates`의 행사별 변경 신호만 전송. 수신 클라이언트는 RLS가 적용된 전체 snapshot을 다시 읽음. 재연결·탭 복귀 시 및 10초 간격으로 복원. 응답 순서가 뒤집혀도 오래된 응답을 적용하지 않음.
- 데모 어댑터: 브라우저 내부 체험 전용. 실제 서버·DB 권한을 대체하지 않음.

## 소유권

| 데이터              | 운영자                          | 참여자            | 심사위원       |
| ------------------- | ------------------------------- | ----------------- | -------------- |
| 행사                | 소속 행사 관리                  | 소속 행사 읽기    | 소속 행사 읽기 |
| 팀·PDF              | 소속 행사 전체                  | 본인 팀만         | 배정 팀만 읽기 |
| PDF 업로드          | 소속 행사 전체                  | 본인 팀만         | 불가           |
| 발표 상태 읽기      | 소속 행사 전체                  | 본인 팀           | 배정 팀        |
| 장표 이동           | 행사 활성 발표                  | 본인 팀 활성 발표 | 불가           |
| 시작·시간 제어·종료 | 가능                            | 불가              | 불가           |
| 평가                | 행사 전체 현황·제출 결과·재개방 | 불가              | 본인 평가만    |
| 평가 항목·초대·배정 | 관리                            | 변경 불가         | 변경 불가      |

모든 데이터에 행사 ID가 있으며 composite FK로 팀·PDF·심사 기준의 행사 간 연결을 제한한다. 비공개 Storage SELECT 정책도 `submissions`와 소속·배정 관계를 검사한다. 브라우저에는 Storage INSERT/UPDATE/DELETE와 테이블 변경 권한이 없다. `finalize_submission` 실행 권한은 service_role에만 있다. 보안 definer 함수는 빈 search_path와 명시적 스키마를 사용한다.

한 사람은 행사마다 하나의 역할을 갖는다. 다른 행사에서는 다른 역할을 가질 수 있다. 행사 최초 생성자가 그 행사의 운영자가 되며, 초대는 해당 이메일의 인증 완료 여부를 확인한다. 초대를 수락한 심사위원은 별도 팀 배정을 받아야 한다.

## 발표 상태 전이

```text
없음/종료 → preparing → running ⇄ paused → ended
                └───────────────→ ended
```

- 시작 클릭에서 동일 컨테이너의 전체화면 요청과 서버 세션 생성을 진행한다. UI 선택 팀과 활성 세션 팀은 별도 상태다.
- `preparing`에서는 시간이 흐르지 않는다. 첫 장표 렌더 성공 후 운영자 `ready` 요청이 서버 `started_at`을 기록한다. PDF 실패 시 재시도 또는 종료 가능.
- `running`에서 pause는 서버 `paused_at`을 기록한다. resume은 정지 구간을 `paused_ms`에 더한다.
- reset은 현재 페이지를 건드리지 않고 기준 시간을 초기화한다. 일시정지 상태에서 reset하면 정지 상태도 유지한다. 확인 대화상자가 필수다.
- ended는 영구 종료 상태로 이동 요청을 거절한다. 새로운 발표는 새 세션을 생성한다.
- `preparing/running/paused`를 활성으로 정의한다. partial unique index가 행사당 활성 세션 하나만 허용한다.
- 세션 생성 시 PDF ID, 페이지 수, 발표 시간·임박 기준·색상을 복사한다. 팀별 시간이 짧으면 임박 기준은 해당 시간 이하로 제한한다. 다음 설정·제출 변경은 현재 세션을 바꾸지 않는다.

남은 시간 = 설정 시간 − (기준 현재 시각 − 시작 시각 − 누적 일시정지 시간). 정지 중은 현재 시각 대신 paused_at, 종료 후는 ended_at을 쓴다. 브라우저 로딩이나 장표 이동은 started_at을 수정하지 않는다. 서버 응답 시각과 해당 snapshot RPC 왕복 시간의 중간값으로 브라우저 시계 오차를 보정한다. 네트워크 비대칭에 따른 작은 오차는 가능하다.

`00:00`까지 카운트다운하고 이후 `+00:01`부터 초과 시간을 표시한다. 상태별 텍스트·아이콘·색상을 같이 표시한다. 종료 임박·초과 색상은 어두운 배경에 대해 4.5:1 이상인지 클라이언트와 DB에서 검사한다.

## 동시성·중복·오류 복구

- 모든 행사 명령은 행사 row `FOR UPDATE`로 직렬화한다. 행사 전체 단일 잠금은 현장 행사의 낮은 쓰기 빈도에 맞춘 단순한 설계다. 대규모 동시 심사에서 처리량이 부족한 경우에만 잠금을 세분화한다.
- `(event_id, actor, request_id)`별 요청 fingerprint와 결과를 같은 트랜잭션에 저장한다. 같은 요청의 재시도는 기존 결과를 반환한다. 같은 ID로 다른 명령을 보내면 거절한다.
- 페이지 이동은 session ID·version·delta를 검증한다. delta는 ±1이고 페이지 범위를 넘을 수 없다. 오래된 버전 요청은 재동기화 후 사용자에게 다시 조작하도록 안내한다. 오래된 명령을 새 버전에 자동 재적용하지 않는다.
- 장표 이동은 `current_page`와 동시성용 `version`만 수정하며 타이머 필드는 유지한다.
- 서버 version과 요청 receipt는 새로고침과 무관하게 보존된다. 네트워크 오류 후 ‘같은 요청 재시도’는 원래 ID를 재사용한다. 확정된 충돌은 최신 상태를 확인하고 새 조작을 한다.
- PDF의 request ID + SHA-256 경로는 재시도 시 같은 파일임을 보장한다. 새 object를 저장하고 이전 submission ID에 대한 CAS가 성공한 뒤 포인터를 바꾼다. 기존 PDF는 먼저 삭제하지 않는다.
- 서버 접근이 없을 때 실시간 반영을 성공한 것처럼 표시하지 않는다. 업로드/명령/심사 오류를 화면에 남기고 재시도를 제공한다.

## 심사 기준과 평가

심사 시작 버튼이 빈 초안을 저장하고 현재 rubric ID를 고정한다. 따라서 첫 점수 입력 전에 기준이 확정된다. 항목 수정은 불변 rubric 새 버전을 만든다. 이전 rubric row는 업데이트하지 않는다.

`(event_id, team_id, judge_id)`는 유일하며 평가 version으로 CAS를 수행한다. 다른 탭의 수정이 먼저 저장되면 현재 입력을 자동 덮어쓰지 않고 충돌을 표시한다. 사용자가 최신 내용을 불러올 때만 입력을 교체한다. 최종 제출은 모든 점수 존재 여부, 숫자 타입, 0~배점, 알 수 없는 항목, 비고 5,000자 제한을 서버에서 검사한다. 임시저장은 일부 점수를 비워둘 수 있다.

최종 제출 후 점수와 비고는 잠기며 운영자만 재개방할 수 있다. 재개방은 기존 기준과 점수를 보존하고 version을 증가시킨다. 운영자 결과에 기준 버전을 함께 표시하고 서로 다른 버전을 무조건 순위로 합산하지 않는다.

## 운영·마이그레이션 주의점

현재 마이그레이션은 신규 설치용이다. 운영 적용 전 DB와 Storage를 백업하고 별도 staging 프로젝트에서 적용한다. 되돌릴 때 기존 점수·PDF를 삭제하는 down migration을 실행하지 않는다. 프런트엔드/Edge 버전을 먼저 되돌리고 DB 변경은 데이터 보존형 후속 마이그레이션으로 수정한다.

활성 세션이 preparing에 남으면 운영자가 발표 화면에서 PDF 재시도 또는 종료를 수행할 수 있다. 멤버 권한 삭제·행사 삭제·보존 기간에 따른 자동 정리는 이번 요구 범위에 포함하지 않았으며, 운영 전에 조직 정책에 맞춰 결정해야 한다.
