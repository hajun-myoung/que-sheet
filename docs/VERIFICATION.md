## 진단 및 한계

- 신규 `event_deletions`는 RLS 활성화와 직접 접근 차단, 본인 삭제 재시도 목록만 RPC로 반환한다. 서버 삭제/메일 선점·완료 RPC는 service_role 전용이다.
- [SECURITY DEFINER 진단](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable)의 신규 2개 공개 RPC는 본인 actor 조회 또는 행사 운영자 검사를 수행한다. [정책 없음 INFO](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)는 비공개 서버 테이블의 의도된 거부 설정이다.
- [익명 사용자 정책 경고](https://supabase.com/docs/guides/database/database-advisors?queryGroups=lint&lint=0012_auth_allow_anonymous_sign_ins)는 코드 로그인 참여자를 지원하기 위한 설정이다. 소속 팀/행사 검사는 그대로 적용된다. [유출 비밀번호 보호 경고](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)는 현재 비밀번호 로그인을 제공하지 않아 이번 범위에서 설정하지 않았다.
- 실제 원격에서 Storage 장애·SMTP 타임아웃을 강제로 발생시키지는 않았다. DB의 정리 재시도 및 발송 결과 불명 상태는 자동 테스트로 확인했다. SMTP의 정확히 한 번 도착은 보장하지 않으며, 불명확한 결과는 명시적 수신 확인 후 재시도한다.
- `CUE_APP_URL`은 현재 localhost. 외부 기기용 발송 전 공개 HTTPS 앱 주소가 필요하다. [메일 설정·템플릿 수정 안내](INVITATION_EMAIL.md).

- 행사별 활성 세션 하나, 중복 request ID 동일 결과, 동일 ID 다른 내용 거부.
- 서버 점수 필수값·범위·타입·알 수 없는 항목 검사, 심사 version 충돌, 최종 제출 잠금과 재개방.
- 기준 새 버전 생성 후 기존 점수·비고·rubric ID 보존.
- 제출 교체 CAS와 이전 세션 PDF 참조 보존.
- 초대 이메일 불일치 거부, 수락 후에도 미배정 팀 자료 접근 거부.
- 타이머 설정 타입·시간 범위·색상 대비 검사.
- 서버 PDF 파서의 확장자·MIME·파일 헤더·빈 파일·20 MiB 초과·손상·500페이지 초과 거부.
- 표준 키보드 리모컨 네 가지 키와 텍스트 입력 제외.

실제 PostgreSQL에서는 별도 연결 두 개를 동시에 호출했다:

1. 발표 시작 두 요청 중 하나만 성공.
2. 동일 요청 ID의 장표 이동 두 요청은 같은 결과를 반환하고 한 페이지만 이동.
3. 같은 버전에서 서로 다른 장표 이동 요청은 하나만 성공.
4. 같은 평가 버전에서 두 탭의 저장 요청은 하나만 성공.

## 아직 검증하지 못한 부분

사용자에게 Supabase 프로젝트가 없어 아래 항목은 코드·SQL 수준 준비를 완료했지만 실제 원격 통합은 검증하지 않았다.

- 실제 Supabase Auth 이메일 로그인, SMTP 발송, 초대 링크 콜백.
- 실제 Storage 업로드·서명 URL·20 MiB 업로드 속도 및 요금제 제한.
- 배포된 Edge Function의 HTTP 전체 흐름과 메모리 제한.
- 실제 두 기기 간 Supabase Realtime 전파·네트워크 단절 후 복구.
- 실제 사용자 JWT를 사용한 HTTP 무단 접근 시나리오(대신 동일 RLS/RPC 정책을 PostgreSQL 역할로 검증).
- 실제 USB/Bluetooth 리모컨, Safari·Firefox·모바일 실기기, 프로젝터.
- 스크린리더 전체 낭독, 장시간 행사 부하, 업로드 중 브라우저 종료와 Storage 제공자 장애.
- 외부 서비스 배포는 수행하지 않음. 사용자 선택에 따라 로컬 데모와 연결 설정을 제공함.

## Supabase 연결 후 인수 검증

1. 운영자 A/B, 팀1 참여자, 팀2 참여자, 심사위원 계정을 별도 브라우저/기기에 로그인한다. 다른 행사도 하나 만든다.
2. 팀1이 PDF를 올리고 운영자 B가 다운로드 없이 미리보기 가능한지 확인한다. 팀2·다른 행사 사용자의 직접 테이블 조회와 signed URL 요청은 거부되는지 확인한다.
3. 운영자 A/B가 동시에 발표 시작을 누른다. 활성 세션은 하나이고 실패한 쪽에는 상태 안내가 보여야 한다.
4. 발표 준비 중 PDF 로딩을 실패시킨 뒤 재시도한다. 준비 전에는 시간이 흐르지 않아야 한다.
5. 10회 이상 장표 이동 후 시작 시각이 유지되는지 확인한다. 참여자 휴대전화에서 다음을 눌러 발표 PC가 같은 페이지를 표시하는지 확인한다.
6. 네트워크를 끊었다 복구하고 새로고침한다. 서버 페이지·시간으로 복원되고 지연된 구버전 요청은 거부되어야 한다.
7. 제출본과 설정을 바꾼다. 현재 세션은 원래 PDF·설정을 유지하고 다음 세션에 새 값이 적용되어야 한다.
8. 심사 두 탭을 열어 서로 다른 값을 저장한다. 두 번째 저장은 충돌 안내, 첫 저장은 보존되어야 한다. 최종 제출을 재전송해도 version/합계가 중복 증가하지 않아야 한다.
9. 운영자가 평가 기준을 변경한다. 이미 시작된 평가는 구버전, 새 평가는 신버전이 적용되는지 확인한다.
10. 정상·임박·초과 색상을 변경하고 실제로 각 상태를 통과시킨다. 전체화면 해제, 재진입, 초기화 취소·승인, 종료 후 이동 차단을 확인한다.

## 실제 리모컨·현장 체크리스트

자동화는 표준 키 이벤트만 확인했다. 다음은 실물 검증 항목이다.

- 장치가 ArrowRight/PageDown 및 ArrowLeft/PageUp을 보내는 키보드형 HID인지 확인.
- USB 수신기 또는 Bluetooth 연결 후 한 번 누를 때 한 장만 이동하는지 확인.
- 길게 누를 때 의도하지 않은 반복 이동이 없는지, 첫·마지막 장에서 범위를 넘지 않는지 확인.
- 검색창·점수·비고에 입력 포커스가 있을 때 장표가 움직이지 않는지 확인.
- 발표 PC를 절전·화면보호기에서 제외하고 실제 프로젝터 해상도에서 PDF 비율·하단 타이머 가림 여부 확인.
- 연결 해제·재연결, 간섭·거리, 배터리, OS별 키 매핑과 실제 전체화면 권한 확인.
