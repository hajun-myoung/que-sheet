# 멤버 등록과 초대 메일

## 사용 순서

1. 행사 설정 → 팀 · 심사위원에서 팀을 등록합니다.
2. 멤버 초대에 이름·이메일·역할(참여자는 소속 팀도)을 입력하고 **멤버만 등록하기**를 누릅니다.
3. 참여 코드 발급 카드에 등록 멤버가 라벨로 표시됩니다. 등록은 수신자 명단 저장이며 Auth 계정이나 멤버십을 생성하지 않습니다.
4. **일괄 초대하기**를 누르고 수신자 수를 확인합니다. 참여자는 팀 코드와 코드가 미리 입력되는 링크, 운영자·심사위원은 이메일 인증 후 수락하는 역할별 초대 링크를 받습니다.
5. 수신자별 발송 대기 / 발송 중 / 발송 완료 / 실패 / 수신 확인 필요를 확인합니다. ‘발송 완료’는 SMTP 서버의 접수 완료이며 받은편지함 도착을 보장하는 의미는 아닙니다.

기존 **초대 링크 만들기**는 수동 전달 방식으로 유지됩니다. 이 방식으로 만든 초대는 일괄 메일 발송 대상에서 제외됩니다. 초대 ID나 팀 코드를 안다는 것만으로 운영자·심사위원 권한을 얻을 수는 없습니다. 직원 역할은 초대 이메일 인증과 수락이 필요합니다.

## 메일 내용을 직접 수정하기

파일: `supabase/functions/send-invitations/template.ts`

- `title`: 메일 제목 (`subject`).
- `intro`, `detail`: 수신자 인사, 행사·역할·팀·코드·유효기간 안내.
- 반환값 `html`: HTML 메일의 색상, 여백, 버튼, 로고, 본문.
- 반환값 `text`: HTML을 표시하지 않는 메일 앱용 일반 텍스트 본문.
- 발신자 표시 이름은 `supabase/functions/send-invitations/index.ts`의 `from.name`에서 수정합니다.

수정 후 다음 명령으로 검사하고 배포합니다(프로젝트 연결 및 Supabase CLI 로그인 필요).

```sh
deno check --node-modules-dir=auto --config supabase/functions/send-invitations/deno.json supabase/functions/send-invitations/index.ts
npm test
npx supabase functions deploy send-invitations --project-ref nidalecwnnxlmxptibua --no-verify-jwt
```

사용자가 입력한 행사명·팀명·이름을 HTML에 넣을 때 `escape()` 처리를 유지하세요. 코드와 초대 링크는 민감한 접근 정보이므로 외부 추적 픽셀·분석 URL에 포함하지 마세요. 참여 코드 링크는 `#code=...` fragment에 코드를 넣어 일반 HTTP 요청 URL에 남기지 않으며, 화면 입력 후 주소창에서 제거합니다.

**Supabase Authentication → Email Templates**는 로그인/인증 메일 수정 화면입니다. 이번에 추가한 일괄 초대 메일은 위 소스 파일에서 수정합니다. 두 템플릿은 별개입니다.

## 서버 설정

[Edge Functions → Secrets](https://supabase.com/dashboard/project/nidalecwnnxlmxptibua/functions/secrets)에 등록합니다. Auth SMTP의 설정값은 Edge Function이 자동으로 읽지 못하므로 별도 등록이 필요합니다.

| 이름                | 예시                                                            |
| ------------------- | --------------------------------------------------------------- |
| `CUE_SMTP_HOST`     | `smtp.gmail.com`                                                |
| `CUE_SMTP_PORT`     | `587` (STARTTLS 필수), 또는 `465` (TLS)                         |
| `CUE_SMTP_USER`     | 전체 Google Workspace 이메일                                    |
| `CUE_SMTP_PASSWORD` | 해당 계정의 Google 앱 비밀번호                                  |
| `CUE_MAIL_FROM`     | 발신 이메일                                                     |
| `CUE_APP_URL`       | 로컬 테스트 `http://localhost:3000`, 실제 운영 `https://앱주소` |

외부 참여자가 자기 기기에서 접속하려면 **공개 HTTPS 앱 주소**를 `CUE_APP_URL`에 설정해야 합니다. localhost는 메일을 연 기기 자신을 가리킵니다. 비밀값은 `NEXT_PUBLIC_*`, Git, 채팅에 넣지 않습니다.

## 중복·실패 처리

- DB에서 행사 잠금과 수신자별 발송 시도 ID로 선점하므로 여러 탭에서 눌러도 같은 발송을 동시에 실행하지 않습니다.
- 이미 발송한 멤버는 다시 누르는 것만으로 재발송되지 않습니다. 새 등록 멤버는 같은 팀의 유효한 코드를 공유합니다.
- 코드 재발급은 이전 코드를 무효화하고 해당 팀의 등록 수신자를 발송 대기로 바꿉니다. 발송 중에는 재발급이 차단됩니다.
- 서버가 거절한 실패는 1분 후 재시도할 수 있습니다. 연결 종료 등으로 실제 전송 여부가 불명확하면 자동 재시도하지 않습니다.
- 발송 중 상태가 2분 넘게 남거나 결과가 불명확하면 수신 여부를 확인한 뒤 **수신 확인 후 재발송 준비**를 누릅니다. 이 명시적 재시도는 중복 메일을 만들 수 있습니다. SMTP는 정확히 한 번 도착을 보장하지 않습니다.
- 발송 도중 탭을 닫으면 미처리 수신자는 대기로 남습니다. 같은 화면에서 다시 일괄 초대할 수 있습니다.
- 팀 코드 원문은 `participant_codes`의 비공개 서버 열에 보관하며, 브라우저 직접 조회는 금지됩니다. 운영자가 명시적으로 새로 발급한 코드만 화면에 반환합니다.

## 행사 삭제

운영 화면 상단에서 **새 행사 만들기**, **행사 삭제**를 사용할 수 있습니다. 삭제는 행사 이름의 정확한 입력을 요구하며 진행 중 발표와 발송 중 메일이 있으면 거절합니다. 해당 행사의 DB 자료를 한 트랜잭션으로 제거한 뒤 Storage API로 PDF를 정리합니다. 다른 행사와 Auth 계정은 유지됩니다.

PDF 정리 실패 시 삭제 기록을 남기고 화면에 **파일 정리 재시도**를 표시합니다. 이미 삭제한 행사의 같은 요청은 재실행해도 다른 행사를 건드리지 않습니다. 제출 중이던 파일은 최종 권한 검사에서 거절되고 업로드 함수가 정리합니다. 장기 중단/런타임 강제 종료에 따른 미참조 Storage 파일은 별도 운영 점검 대상입니다.
